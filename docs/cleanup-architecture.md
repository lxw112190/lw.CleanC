# 清理架构与规则扩展

自 0.4.0 起，文件清理统一进入“分类清理”。软件名称、缓存类别和是否需要确认不会产生新页面。

## 分工

| 层次 | 职责 | 扩展位置 |
| --- | --- | --- |
| JSON 规则 | 名称、分类、允许路径、文件类型、进程、保留期、影响、额外确认条件 | `rules/default.rules.json` 或个人 `Data/rules.json` |
| 清理处理器 | 发现候选、核验使用状态、核验每个候选的路径和类型 | `ICleanupHandler`，在 `CleanupHandlers` 中注册 |
| 统一引擎 | 规则验证、按处理器扫描、结果和状态汇总、统一清理入口 | `CleanupEngine` |
| 删除管线 | 检查确认、排除项、文件身份、独占句柄、持久化意图及结果日志 | `Cleaner` / `NativeFile` |
| WPF 界面 | 项目勾选、预览、搜索、分页、确认条件、进度和记录 | 不根据具体软件增加页面 |

`files` 处理允许范围内的普通缓存，保留天数为 1–3650。`vs-installer-temp` 识别用户 Temp 下具有 VS 包目录特征的负载，按安装目录分别输出项目，不使用保留天数，必须确认安装结束。

0.5.0 的近期浏览器选项通过一次扫描的 `CleanupScanOptions` 传入，结果明确携带 `IncludeRecentFiles`。它不修改 JSON 的保留期；只有路径策略认定的浏览器缓存规则可以启用。前端修改选项后使旧预览失效；后端重新验证适用范围、固定浏览器进程及必需确认，审计日志记录每个项目的该状态。

Windows 系统维护和 uv 官方清理继续委托现有系统/应用工具。它们可能处理整个缓存，不能声称仅删除文件预览中的项目；JSON 不能指定可执行程序或任意命令。

## 新增普通缓存

在规则数组中添加项目，`handler` 省略时就是 `files`。可以配置 `fileExtensions` 缩小类型范围、`reviewRequired` 要求单独勾选、`confirmation` 增加必须确认的条件。程序自动展示该项目和条件，使用同一预览和清理流程。

`fileNamePatterns` 补充文件名白名单，支持 `*` / `?`，与扩展名过滤取交集。腾讯日志仍受 `DiagnosticLogs` 的固定范围约束，清空规则过滤不能放开其他文件。`BrowserCaches` 集中描述浏览器根目录、缓存叶子和固定进程，供路径验证与配置发现共用。

规则仍受 C# 路径白名单约束。新的目录超出允许范围时，需要审查并修改 `PathPolicy`，不能仅靠 JSON 放开系统目录。

## 新增处理机制

实现 `ICleanupHandler` 的扫描、状态核验和逐文件验证，在 `CleanupHandlers` 的定义表注册工厂、必需确认条件及保留期行为，同时补充路径策略和回归测试。新处理器输出 `RuleResult` / `FileCandidate`，不自行删除文件，也不新增页面。

一个规则可按 `Scope` 输出多个项目，例如同一种安装包的两个临时目录。每个目录独立勾选；确认条件按规则汇总。改变任何勾选范围后，界面清除之前的确认。后端再次验证确认，不能依赖按钮状态。

## 归属和保护

- 普通文件规则不得扫描或删除已识别的安装包负载，安装包规则被删除后这项限制仍生效。
- 唯一的共享根目录例外是普通 `files` 与 `vs-installer-temp` 共用当前用户 Temp；其他重叠仍被拒绝。不能注册两个重叠的安装包规则重复统计。
- 安装包处理器使用 C# 中固定的目录特征和类型白名单。JSON 的类型过滤只能缩小候选范围，无法扩大范围。
- 必需确认条件由注册定义提供，JSON 只能增加条件。安装进程、Windows 更新待重启标记和相关文件操作继续拦截；无法核验时也阻止安装包清理。
- 一次清理预览在所有规则之间共享十万候选上限。到达上限后保留已收集的文件，标记未扫完或尚未扫描的项目。单项重扫使用剩余预算，预算已占满时可只扫描该项。
- 清理时重新核验状态、候选路径、排除项和文件身份。混合勾选使用同一份逐文件审计日志，记录所确认的条件；占用或变化的文件跳过。
